A CROSS-REGION REPLICATION LAB

GOLDENGATE
ON AZURE.

How does a change reach
the other database?

In this lab, I use two private Autonomous Databases. We’ll follow an INSERT from West Europe to Southeast Asia, then test conflicting updates.

↓ START WITH THE ARCHITECTURE
WEST EUROPE ↔ SOUTHEAST ASIAONE DATABASE AND ONE GOLDENGATE DEPLOYMENT IN EACH REGION

01 / ARCHITECTURE

ONE PAIR
PER REGION.

Each database has a local
GoldenGate deployment.

Applications can write to either database. GoldenGate captures local changes and applies those received from the other region. The two databases are replicated asynchronously.

LOCAL CAPTURE AND APPLY IN BOTH REGIONS

02 / PRIVATE CONNECTIVITY

CONNECT
THE REGIONS.

First, let’s look at the network.

Each deployment connects to its local database over TLS. The deployments exchange trails over WSS. VNet peering, security rules and private DNS support these connections.

TLS / 1521WSS / 443
TWO LOCAL OGG–DB PEERINGS · ONE CROSS-REGION OGG PEERING

03 / INTEGRATED EXTRACT

CAPTURE
AN INSERT.

We insert row 101 in West Europe
and commit the transaction.

EWEU captures the change from the local database and writes it to trail ew. At this point, row 101 is not yet in the Southeast Asia database.

INSERT INTO REPLICATION_TEST
VALUES (101, 'WEU', 'NEW_ROW');
COMMIT;
LOCAL INTEGRATED EXTRACT · DOWNSTREAM CAPTURE DISABLED

04 / DISTRIBUTION PATH

SEND THE
TRAIL.

PWEU sends the record
to Southeast Asia.

The Distribution Path reads trail ew and connects to the remote Receiver using WSS on port 443. It uses the assigned GoldenGate connection and the remote deployment’s FQDN.

DEDICATED GOLDENGATE CONNECTION · WSS / TCP 443

05 / RECEIVER AND REPLICAT

APPLY THE
INSERT.

The record has arrived.
Now Replicat applies it.

The Receiver writes the incoming trail. RSEA reads that trail and inserts row 101 into the Southeast Asia database. Both databases now contain the row.

RECEIVER → INCOMING TRAIL → RSEA → DATABASE

06 / UPDATE CONFLICT TEST

UPDATE
THE SAME ROW.

What happens if both regions
update row 101?

For this test, start with matching copies and stop both Replicats. Leave Extracts and Distribution Paths running. Update the row in WEU at T1, then in SEA at T2.

The row-change timestamp T2 is later than T1.
BOTH REPLICATS STOPPED · CAPTURE AND TRANSPORT STILL RUNNING

07 / AUTO-CDR

RESOLVE
THE CONFLICT.

Restart both Replicats
and compare the values.

With ROW-mode Auto-CDR, the later row-change timestamp determines the result in this test. SEA retains T2, and WEU applies T2 over T1.

Reversing the timestamp order would change the result; SEA has no priority.
BOTH DATABASES NOW HOLD THE T2 VALUE

08 / LOOP PREVENTION AND MONITORING

PREVENT
LOOPS.

The applied transaction must not
be captured again.

Each Replicat sets tag 01, and its local Extract excludes that tag. Checkpoints record progress; heartbeat tables help you check replication lag.
